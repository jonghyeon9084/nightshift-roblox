# 오늘도 정상영업 — 재방문·성장 기획 초안

작성: 2026-10-31 / NightShift-Planner / NightShift-CommerceContract.
기준: `../../AGENTS.md`, `../commerce-expansion-brief.md`; 기존 `../implementation/contract.md`, `../implementation/integration-report.md`, `../../src/shared/Config.luau`를 참고했다.
최신 확장 요구를 우선한다. 이 문서는 플레이 흐름과 수용 기준을 제안하며 API·Remote 필드·저장 스키마·공개 상수를 확정하거나 변경하지 않는다. 실행 기준은 Integrator의 commerce-contract 및 CommerceConfig이며 아래 수치는 모두 **미검증 밸런스 가설**이다.

## 1. 사실과 가설의 경계

- 기존 보고서에 실제 1클라이언트 입장·집기·접수·정전 해결·5건 완주·결과 복귀가 기록돼 있다. 이번 작성에서 재실행하지 않았다.
- 기존 실제 월드는 4매장이고 Config도 4매장·3상품이다. 8매장·11상품·물류·영구 저장이 이미 작동한다고 볼 수 없다.
- 약 52초 완주는 자동화 입력 기록이다. 사람의 첫 판매 시간·협동 난이도·재미·D1/D7·매출은 미측정이다.
- 아래 시간·XP·레벨·보호 기간·상품 수요·유료 후보는 구현 및 독립 검토·플레이 테스트 전 제안이다. 클라우드 저장·음성 연결·16인 부하·모바일 통과를 주장하지 않는다.

## 2. 첫 5분: 주문부터 첫 판매까지

목표 가설: 처음 온 사람이 음성이나 친구 없이 첫 판매까지 이해하고, 다음 교대를 선택할 이유 하나를 발견한다. 첫 5분은 입장부터의 안내 구간이며 기존 근무 제한 300초를 늘린다는 뜻이 아니다.

| 입장 후 목표 시간 | 실제 플레이와 안내 | 완료 판정·막힘 회복 |
| --- | --- | --- |
| 0:00~0:40 | Hub에서 빈자리·친구 소속을 확인하고 8매장 중 선택. 도로 양쪽 4매장, 앞문·사무실·하역·진열·계산대를 한 방향 안내로 연결한다. | 소속과 방문 중인 매장을 따로 표시. 화면에 다음 행동 하나만 강조한다. 혼자 연습도 무료. |
| 0:40~1:20 | 사무실 PC에서 물 또는 빵 소량 주문. 개인 지갑과 이번 교대 운영자금, 실재 공유 재고·다음 재입고·매장 주문 한도를 구분한다. | 서버 주문 확정 후에만 배송 안내. 품절이면 재시도 연타 대신 재고 있는 기본품으로 전환; 비용 부족이면 구매 불가 이유와 가능한 수량 표시. |
| 1:20~2:20 | 도착 트럭의 한 상자를 직접 집어 하역→빈 진열 칸까지 운반한다. 경로는 도로 차도보다 인도를 유도한다. | 같은 팀 중 한 명이 운반해도 팀 안내 진도 공유. 끼임·이탈 시 계약의 안전 반환 사용; 상품 복제나 자동 판매 없음. |
| 2:20~3:30 | 칸 하나를 직접 선택해 진열하고 손님 주문을 계산대에서 판매한다. 물건명·수량·모양을 함께 표시한다. | 첫 손님은 해당 점포가 진열 완료한 기본품을 요구하도록 제안. 확정된 판매 한 건 뒤 매출·보상·재고 감소를 확인한다. |
| 3:30~5:00 | 재주문 또는 팀원에게 운반 핑. 첫 결과에서 무료 해금까지의 진도와 다음 교대 목표 하나를 안내한다. | 첫 판매 전에는 약탈·희귀 주문을 주목표로 띄우지 않는다. 무음 경보 읽기 연습은 텍스트 예시로 제공하며 실제 도난으로 위장하지 않는다. |

기본품 8종 전체가 레벨 1부터 주문 가능하다. 첫 화면 추천 두 품목은 안내 순서일 뿐 품목 잠금이 아니다. 첫 재고를 개인 전용으로 몰래 생성하지 않는다. 공유 재고가 모두 소진된 경우 모두에게 같은 재입고를 보여주고, 첫 판매 막힘을 재입고 설계의 실패 지표로 집계한다.
음성은 선택 기능이다. 주문 요청·하역 도움·빈 진열 칸·경보 위치 핑과 상품명 텍스트만으로 같은 과정을 완료해야 한다.

## 3. 한 교대와 다음 교대

한 교대는 준비→소량 주문→배송·직접 진열→판매·사건 대응→결산→무료 재준비로 이어진다. 기존 최대 300초·5건 성공 구조와 물류를 합쳤을 때의 시간 여유는 미검증이며, 별도 수치 변경은 계약 담당이 결정한다.

| 구간 | 선택과 역할 | 다음 플레이 동기 |
| --- | --- | --- |
| 준비 | 현재 수요·도매 재고를 보고 예산 범위 내 주문. 1인은 작은 주문, 2~4인은 주문/운반/진열·계산/순찰을 자율 분담. | 역할별 유료 자격 없음. 역할 고정 없이 중간 교대 가능. |
| 영업 | 기본품 판매가 주 수입. 진열 슬롯·트럭 도착·점포 재고를 보며 두 번째 주문을 선택. | 친구의 운반을 기다리는 동안 계산·다른 기본품 진열 수행. |
| 변주 | 기존 정전과 안내를 보존하고 희귀 납품·수요 변화는 첫 판매 뒤 소개. | P0에서는 기존 정전 외 새 사건을 계속 중첩하지 않는다. |
| 위기 | 도난 경보→남은 재고로 영업 유지 또는 짧은 회수 선택. | 회수 포기해도 교대를 계속하고 무료 재주문 가능. 약탈이 필수 과제는 아님. |
| 결산 | 판매·운반·협동 기여, 운영자금 잔액, 개인 보상, 지원/연습 여부를 각각 보여준다. | 무료 재준비와 퇴장 동등 노출. 다음 해금·미발견 상품 중 목표 하나를 제안. |

운영자금은 교대 공용이고 개인 영구 지갑은 별도다. 운영자금 잔액을 개인에게 자동 전환하지 않는다. 재접속·점포 이동·중도 이탈로 초기 자금이나 최초 보상을 반복 수령할 수 없어야 한다.
점포 기록과 개인 기록을 분리하고 팀 인원·도구 단계·지원/연습 여부가 다른 결과는 구분해 보여준다. 유료 외형은 기록 조건이나 점수에 영향을 주지 않는다.

## 4. 무료 레벨 도구 해금표

아래는 **누적 XP 기준 제안**이다. 실제 레벨·도구 식별자·운반량은 CommerceConfig에서만 확정한다. 해금 후 기본 도구 사용에 Robux나 반복 대여료를 요구하지 않는다.

| 레벨 / 누적 XP 제안 | 무료 해금 | 제한과 플레이 의미 |
| --- | --- | --- |
| 1 / 0 | 기본 한 묶음 운반, 전 기본품 주문·직접 진열·판매·경보·핑, 기본 외형, 배치 저장 1칸 | 첫 플레이 핵심 루프 전체 가능. 희귀품도 등장 시 게임머니로 주문 가능. |
| 2 / 100 | 자기 점포 손수레 | 자기 점포 소유품 최대 2묶음 제안. 훔친 물품에는 적용하지 않아 도난량·도주력 우위 방지. 통로 통과 검증 필요. |
| 3 / 250 | 재고 스캐너 | 기존에 무료로 볼 수 있는 자기 매장 수량을 요약. 공용 희귀 입고 정보를 먼저 받거나 숨은 상대 재고를 탐지하지 않는다. |
| 4 / 450 | 진열 배치 프리셋 | 배치 계획·빈 칸 안내를 복원. 상품 생성·상자 순간이동·일괄 자동 진열은 하지 않는다. |
| 5 / 700 | 무료 배치 저장 2번째 칸·작업복 색상 | 기본 저장 1칸 유지, 꾸미기 선택 확장. |
| 6 / 1000 | 플레이 획득 간판·손수레 외형 | 능력치는 동일. 이후 해금 확장은 P1로 분리. |

XP 제안: 검증된 판매 기여 +10, 처음 배송된 자기 점포 상품의 진열 기여 +5, 교대 완주 +30. 같은 상품 반복 집기·놓기·반환·도난/회수 왕복에는 XP 없음. 협동 사건 보상은 서버가 확정한 해결에 교대당 한 번 +10을 제안한다.
판매/운반 기여는 거래·상품 단위로 한 번만 인정하고 인원이 늘었다고 총보상을 인원수 배로 무조건 증식시키지 않는다. 기여 배분은 Economy가 확정한다. 단독 무료 도구 해금도 가능해야 하며 팀 전용 XP나 매일 접속 보너스를 필수로 두지 않는다.
첫 정상 교대에서 레벨 2 진도가 보이고 여러 교대에 걸쳐 도구가 늘어나는 속도를 목표로 한다. XP 제안만으로 실제 도달 시간을 보장하지 않는다. P0에서 수동 여러 교대 실측 후 조정한다.

| 회수 선택 | 회수 기회 30초와 피해 점포별 재도난 대기 90초를 초기 제안. 정확한 소유권 이전·회수 대상·기한은 계약에서 확정. | 피해자는 무료 핑으로 대응. 무료 안전 반환/도난 회수는 구분하며 유료 부활·경보 해제·보상 구매 없음. |
| 회수 실패 | 남은 기본품 판매→PC 대체품 소량 주문→진열로 복귀. 잃은 재고를 즉시 동일 수량 복제 보상하지 않는다. | 점포 운영자금이 고갈될 때의 무료 재준비 제공. 실패 안내에 상점 팝업 없음. |
| 저장 장애 | 개인 영구 진행과 이번 Studio 임시 진행을 분명히 구분. 로드 실패 시 원래 데이터 보존을 우선하고 영구 보상 거래를 확정하지 않는다. | 제한 재시도/안전 대기·재접속 안내. 기본 프로필 덮어쓰기 금지. 임시 플레이를 허용할지는 Profiles/Server 계약으로 결정. |

약탈을 성장의 주 경로로 만들지 않는다. 도난 자체에는 XP·반복 도전 보상을 주지 않으며, 훔친 상품 처리 수익과 회수 기한을 계약이 정해야 한다. 성공 약탈의 분당 순수익이 정상 운반·판매보다 지속적으로 높거나 동일 피해점 반복 이탈이 늘면 먼저 상한·대기시간·매각 규칙을 조정한다. 유료 보호막은 대안이 아니다.

## 6. 여러 날의 재방문

- 두 번째 방문: 저장된 레벨·도구·기본 배치와 개인 기록을 확인하고 새 기본품 동선 또는 스캐너 해금을 목표로 선택한다. 저장 실패를 새 계정 진행처럼 표시하지 않는다.
- 여러 교대: 수요 변화·다른 기본품 배치·다른 친구 역할·희귀 발견 중 원하는 목표를 고른다. 모든 날 같은 출석 작업을 강제하지 않는다.
- P1 주간 도전 예: 서로 다른 기본품 4종 판매, 협동 정전 2회 해결, 새 진열 계획으로 한 교대 완주. 무료 외형 보상은 후속 주차에도 플레이로 얻을 경로를 둔다. 음성·약탈 참여·결제를 조건으로 넣지 않는다.
- 친구 재방문: 결과 화면에 함께한 팀과 다음 역할 제안만 표시한다. 연락처 접근·자동 외부 초대·메시지 전송은 하지 않는다.
- 쉬었다 돌아와도 레벨·수집·프리셋 유지. 오프라인 재고 부패·미접속 세금·연속 접속 끊김 손실 없음. 서버 단위 재고·교대 운영자금의 재생성은 개인 영구 저장과 구분한다.

## 7. 비강압 유료 후보

실제 상품 생성·Robux ID/가격·판매·결제 호출은 이번 범위 밖이며 기본 비활성이다. 아래는 판매 효과가 검증되지 않은 후보 목록이다.

| 후보 | 무료 대응 기능 | 설계 제한 |
| --- | --- | --- |
| 달빛/레트로 손수레·스캐너 외형 | 레벨 해금 기본 도구·플레이 외형 | 속도·적재·도난량·사거리·알림 시각 동일. 가독성·충돌 크기 동일. |
| 배치 프리셋 추가 저장 칸 | 레벨 1의 1칸, 레벨 5의 2칸 제안 및 수동 편집 | 저장 선택만 증가. 실제 진열 수·자동 진열·주문 처리량·점수 보너스 없음. |
| 간판·유니폼 묶음 | 기본 간판/작업복과 플레이 해금 색상 | 상대 경보·상품명·소속 표시를 가리거나 보호 점포로 위장하지 못함. |

유료 후보는 플레이어가 직접 연 꾸미기 화면에 정가·구성·무료 대안을 명료하게 보여주는 방향으로 검토한다. 도난·실패·품절·저장 장애 화면에는 구매 제안을 붙이지 않는다. 유료 랜덤 보상·기한 압박·희귀 선점·점수·경보 무효화·과금 역할을 제외한다.

## 9. 측정 계획과 독립 검토

이벤트 이름·필드는 새 Remote 계약이 아니라 분석 요구다. 서버가 확인한 첫 주문/도착/첫 진열/첫 판매/도난 피해/회수/교대 결과를 활용하도록 Server가 설계한다. 개인 정보·음성·대화 내용을 수집하지 않는다.

| 지표 | 비교·판정 계획 | 현재 결과 |
| --- | --- | --- |
| 첫 판매 완료율·소요시간 | 첫 참여자 기준 분모, 입장→확정 판매. 주문/배송/진열/품절 단계별 막힘 분리. 5분 내 첫 판매는 목표 가설. | 미측정 |
| 첫 도난 후 이탈·재도전 | 피해 뒤 2분 내 이탈, 다음 교대 시작, 회수 선택/성공을 구분. 이탈의 원인을 도난으로 단정하지 않음. | 미측정 |
| 정상 영업 대 약탈 수익 | 동일 팀 인원·도구 단계·플레이 시간으로 수익/분·피해 집중도 비교. | 미측정 |
| 친구와 재방문·D1/D7 | 첫 플레이 날짜 집단의 다음날/7일 후 재방문 정의를 고정한 뒤 집계. 소규모 로컬 표본을 유지율로 제시하지 않음. | 미측정 |
| 무료 도구 접근·저장 회복 | 단독/협동의 해금까지 교대 수, 재접속 보존, 장애 중 잘못된 성공 표시를 확인. | 미측정 |

다음 독립 DesignReview 담당에게 공정성·첫 판매 막힘·도구 우위·보상 악용을 읽기 전용 검토 요청할 준비가 됐다. 이 문서 작성 자체는 독립 검토 통과가 아니다. 검토 항목별 수용·변경·보류 이유는 이후 결정 기록에 남긴다.

## 10. 계약 조율 사항과 차단 요인

1. **P0 조율:** 기존 300초/5주문/3상품 정적 선반을 실제 물류·11상품으로 확장할 때 첫 판매 준비 구간과 손님 요구품 생성 규칙을 정해야 한다. 진열 전 품절품 요구로 첫 진행이 막히면 안 된다. 기존 contract/Config를 여기서 수정하지 않았다.
2. **P0 조율:** 첫 보호 영업의 저장 기준·혼합 숙련 팀·빈 점포 전환, 재도난 대기와 회수 종료/소유권 이전/훔친 상품 매각 규칙이 필요하다. 위 30/90초는 상수가 아닌 제안이다.
3. **P0 조율:** 무료 레벨 도구·XP·무료 프리셋 수와 실제 Config 일치 필요. 프리셋은 계획만 복원하며 직접 진열을 대체하지 않는다는 요구를 고정한다.
4. **P0 조율:** 재고 전량 품절/운영자금 고갈/로드 실패에서도 무료 재준비와 안전한 원본 저장 보존을 함께 보장해야 한다. 공유 재고 밖 비공개 튜토리얼 지급이나 운영자금의 영구 지갑 전환을 추가하지 않는다.
5. **검증 차단:** 신규 물류·다중 클라이언트·16인·모바일·클라우드 저장·음성의 실증은 아직 없다. 현재 문서 작성 차단은 없으며 실제 게임 검증은 담당 구현과 메인 Studio 통합 뒤 진행한다.

수치가 commerce-contract/CommerceConfig와 다르면 구현자는 계약을 따르고 차이를 Planner/Moderator에게 돌려보낸다. 이 초안에서 미완성 API 이름을 만들어 다른 담당 소스에 의존시키지 않는다.
