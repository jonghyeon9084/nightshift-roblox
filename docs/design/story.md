# 오늘도 정상영업 — 스토리 기획

- 작성: NightShift-Story / 2026-10-31. 상태: 통합 전 제안, 구현·플레이 검증 전.
- 근거: 프로젝트 AGENTS.md, docs/planning-brief.md, docs/game-brief.md 및 이번 위임.
- 범위: 이 문서만 작성. 핵심 조작·사건 일정·승패 규칙은 기획 그룹이 최종 결정한다.
- 구분: 1밤은 첫 5분 프로토타입, 2·3밤은 같은 매장을 재사용하는 후속 콘텐츠다.

## 이야기의 중심
- 한 줄: 두 야간 직원이 길을 잊은 작은 편의점에서 마지막 장보기를 마치고, 손님과 가게를 아침으로 돌려보낸다.
- 배경: 골목 끝 편의점은 동네 사람들이 귀가 직전 들르던 곳이다. 점포명은 게임 제목을 사용한다.
- 오래된 인수인계 장부에는 팔린 물건은 적혀 있지만, 끝내 건네지 못한 주문들이 남아 있다.
- 가게는 그 주문을 기억하느라 밤마다 서로 다른 날의 진열을 꺼내 놓는다.
- 같은 밤의 시간 여행이 아니라, 정리하지 못한 서로 다른 밤이 현재 영업에 겹치는 현상이다.
- 상품은 익숙한데 놓인 자리가 달라지고, 아무도 없는 통로에서 예전 호출벨이 울린다.
- 손님은 위협하는 존재가 아니다. 집에 가기 전 사려던 것이 있었을 뿐이며 정체를 단정하지 않는다.
- 주문을 전달하면 그 밤의 장보기 하나가 끝난다. 다섯 건은 이번 근무에 배정된 분량이다.
- 정전은 매장과 창고가 서로 다른 밤을 떠올릴 때 생긴다. 두 곳을 맞추면 오늘의 불이 돌아온다.
- 불안도는 가게의 기억이 뒤섞인 정도다. 최대가 되면 이번 근무가 접히고 팀 전체가 재도전한다.
- 직원은 죽거나 버려지지 않는다. 실패 문구는 동료 탓이나 숨겨진 벌을 암시하지 않는다.

## 두 사람이 필요한 이유
- 전 근무자의 메모: “매장에선 켜지는 순서가 보이고, 창고에선 스위치가 닿아요.”
- 한 명은 매장 표시등을 읽고 기존 신호로 전달하며, 다른 한 명은 차단기를 조작한다.
- 신호는 점포의 기존 업무 도구라는 설정이다. 대사 입력·음성·이름 부르기를 요구하지 않는다.
- 두 직원은 특별한 능력이나 고정 직업이 없다. 서로 본 것을 알려주는 행동이 이야기의 해결이다.
- 주문 받기·찾기·전달 역시 “내 쪽에 있나 볼게”라는 일상적 협력을 떠올리게 한다.
- 이야기상 두 사람이 필요하다는 설명이 이탈 시 영구 교착을 정당화하지 않는다. 처리는 기획 규칙을 따른다.

## 첫 5분 최소 삽입본 — 1밤 「자리만 조금 달라요」
- 필수 범위: 아래 안내 메모 1개, 시작·정전·복구·결과의 짧은 UI 문구, 마지막 후크 1줄.
- 별도 대화창·성우·컷신 없이 기존 목표 UI와 결과 UI에 붙이는 문안이다.
- 안내 메모는 계산대에 고정한 종이 Part와 텍스트로 제시하며, 읽기·수집을 완료 조건에 넣지 않는다.
- 첫 진입 / 시작 문구: “첫 야간이네요. 자리가 달라도 물건은 여기 있어요.”
- 계산대 메모 / 첫 줄: “오늘 할 일: 주문 5건 · 정전 해결 · 근무 종료.”
- 계산대 메모 / 둘째 줄: “불이 꺼지면 매장 한 명, 차단기 한 명. 표시등 순서를 신호로 전해요.”
- 상품은 기획에서 정한 3종만 사용한다. 스토리 전용 물건·여섯 번째 주문은 추가하지 않는다.
- 주문 문구는 상품명과 수량을 우선하며, 상품이 바뀌어도 대응하도록 이름을 대사에 고정하지 않는다.
- 정전 시작 / 안내: “서로 다른 밤이 켜졌어요. 표시등 순서를 동료에게 알려 주세요.”
- 차단기 쪽에는 기존 조작 도움말을 유지한다. 분위기 문구가 실제 입력 방법을 대신하지 않는다.
- 정전 해결 / 문구: “맞아요, 지금 불빛이에요. 영업을 이어 가요.”
- 성공 대기 / 목표 UI: 주문 수·정전 해결 여부·근무 종료 여부를 기존 상태대로 계속 보여 준다.
- 팀 성공 / 결과: “오늘도 정상영업. 마지막 장보기가 끝났습니다. 두 분도 퇴근하세요.”
- 성공 후크 / 결과 하단: “내일 인수인계: 진열표가 먼저 출근해 있습니다.”
- 팀 실패 / 결과: “오늘 기록이 섞였어요. 두 분 함께 이번 근무를 다시 시작할 수 있어요.”
- 실패 후에는 성공 후크를 노출하지 않고 기존 재도전 동선으로 연결한다.
- 1밤 환경 단서: 진열표의 작은 ‘어제 자리’ 글씨와 현재 상품 위치가 어긋난다.
- 이 단서는 선택 사항이다. 현재 상품명·위치 안내와 헷갈리면 첫 프로토타입에서 제외한다.
- 빈 통로 호출벨은 기존 사건을 활용한다. 손님 탐색·추격·응답 의무를 새로 만들지 않는다.

## 첫 한 밤의 간단한 결말
- 기존 성공 조건 세 가지가 모두 충족된 결과 화면에서만 ‘퇴근’ 문구를 보여 준다.
- 장부의 오늘 칸에 ‘마감’ 텍스트를 표시하면, 이번 밤의 이야기는 여기서 완결된다.
- 문 열기·두 명 동시 서명·추가 버튼·특정 위치 집합을 별도 성공 조건으로 요구하지 않는다.
- 여유가 있으면 매장 조명 색을 평소의 따뜻한 색으로 복귀시키되, 결과 확인을 지연시키지 않는다.
- 다음 밤 후크는 짧은 여운이다. 첫 버전에서 2밤이 구현되지 않았다면 시작 버튼이나 해금 약속을 붙이지 않는다.
- 재도전은 새 근무 시작으로 설명한다. 첫 버전에는 밤 진행 저장이나 연속 3밤 완주를 요구하지 않는다.

## 후속 2밤 「먼저 온 진열표」
- 추가 시점: 첫 한 밤의 협동·성공·실패·재시작 검증 후. 기존 방 크기와 상품 3종을 유지한다.
- 변화: 허용된 상품 배치를 바꾸고, 진열표 아래에 지난 근무의 작은 손글씨를 붙인다.
- 시작 대사: “진열표가 먼저 왔네요. 물건은 아직 자기 자리를 고르는 중인가 봐요.”
- 주문 중 선택 대사: “늦어도 괜찮아요. 집에 가기 전에 이것만 있으면 돼요.”
- 계산대 메모: “벨이 울려도 통로가 비어 있을 수 있어요. 오래 기다린 소리가 먼저 도착하거든요.”
- 창고 메모: “혼자 고치려다 아침을 놓쳤어요. 오늘은 보이는 쪽에서 알려 주세요.”
- 환경 단서: 창고 벽의 오래된 근무표에 두 칸이 있고, 한 칸만 연필 자국이 남아 있다.
- 이 자국은 과거 직원의 서툰 인수인계 흔적이다. 실종·죽음·범인 찾기 퀘스트로 확장하지 않는다.
- 정전 복구 대사: “이번엔 기다리는 쪽도, 고치는 쪽도 혼자가 아니었네요.”
- 성공 문구: “둘째 기록 마감. 기다리던 주문이 오늘 날짜를 받았습니다.”
- 후크: “다음 인수인계: ‘고맙습니다’ 뒤에 빈칸을 남겨 주세요.”
- 배치·사건 순서는 기획의 허용 조합을 따른다. 메모가 특정 정전 시각이나 정답 순서를 고정하지 않는다.

## 후속 3밤 「빈칸까지 정상영업」
- 변화: 같은 장부의 미처리 문장이 줄어든다. 새 방·새 손님 시스템 없이 텍스트만 교체한다.
- 시작 대사: “오늘은 기록이 짧네요. 다 끝내면 저도 불을 조금 쉬게 할게요.”
- 계산대 메모: “물건을 건넨 뒤에는 빈칸을 두세요. 돌아오는 길까지 우리가 적을 필요는 없으니까요.”
- 마지막 주문 선택 대사: “이제 집에 갈 수 있겠네요. 두 분도 너무 늦지 마세요.”
- 이 대사는 주문 완료 때만 보이며, 주문 5건 달성만으로 근무 전체가 끝났다고 표시하지 않는다.
- 환경 단서: 이전의 ‘미전달’ 칸이 비어 있고 종이 모서리에 ‘다녀오겠습니다’가 적혀 있다.
- 마지막 정전도 동일한 두 사람 협동이다. 새로운 입력·의식·아이템 소비를 추가하지 않는다.
- 정전 복구 대사: “잘 들었어요. 이제 같은 아침을 보고 있네요.”
- 성공 결말: “밀린 기록 마감. 가게는 처음으로 오늘의 날짜를 기억했습니다.”
- 다음 밤 후크: “새 인수인계: 내일은 처음 오는 손님이 있습니다. 평소처럼 맞아 주세요.”
- 세 밤의 매듭은 과거 주문의 정리다. 앞으로의 영업은 새 이야기이며 영원히 탈출 못 한다는 결말이 아니다.

## 구현 전달 기준과 범위 경계
- 필수 문구는 짧게 나누어 표시하고 이동·상품 전달·신호 UI를 가리지 않는다. 반복 열람은 강제하지 않는다.
- 표시 시간·줄바꿈·화면 크기별 가독성은 클라이언트 담당과 메인이 정한다. 서사 때문에 타이머를 멈추지 않는다.
- 목표와 표시등의 숫자·기호는 기획 규약이 우선이다. 색상만 읽게 하거나 이야기로 정답을 숨기지 않는다.
- 전 근무자는 메모의 필자일 뿐이다. NPC 모델·새 음성 자산·대화 선택지 구현은 필요하지 않다.
- 필요한 장식은 종이·작은 표지·장부를 나타내는 기본 Part와 직접 작성한 UI 텍스트뿐이다.
- 상표·기존 IP·유명 캐릭터를 인용하지 않는다. 외부 에셋·유료 API·실제 상품 생성은 사용하지 않았다.
- 스토리와 정상 결말은 무료로 완결한다. 결말·단서·정전 도움말을 판매 대상이나 구매 유도로 쓰지 않는다.
- 이번 문서는 아이템·수익화 체계를 추가하지 않는다. 해당 담당의 선택형 외형도 핵심 안내를 가리지 않아야 한다.

## 기획 충돌·확인 요청
- 현재 초안과 직접 충돌하는 승패 변경은 없다. 주문 5건·정전 해결·근무 종료 및 팀 실패를 그대로 전제했다.
- 해석 주의: ‘초기 3밤’은 콘텐츠 제안이며 첫 버전의 필수 구현 범위를 3배로 늘리자는 요구가 아니다.
- 변경 제안: 없음. 추가 상태 저장 없이 첫 밤을 끝내며, 후속 밤 선택·진행 방식은 이후 기획에서 결정한다.
- 정전 연출 일정과 문구 노출은 실제 사건 발생에 연결한다. 특정 분·주문 번호에 묶인 별도 스토리 트리거는 만들지 않는다.
- 확인할 테스트: 두 초심자가 음성 없이 메모와 기존 UI로 역할을 나누고 정전을 해결하는지 관찰한다.
- 확인할 테스트: 주문 5건만 완료했을 때 퇴근으로 오해하지 않는지, 실패 문구를 개인 책임으로 받아들이지 않는지 확인한다.
- 재미·친근함·재방문 효과는 가설이다. 독립 기획 검토, UI 가독성 검증, Studio 2인 플레이는 아직 실행하지 않았다.
