## SD2. 유지하는 결정과 가설
- 기존 R1: 자동 복구는 공동 해결 성공이 아니다. 다인에서도 지원 마감·무료 재도전·모든 일정 접근을 유지한다.
- 기존 R2: 사건은 주문 성공 단계에 연결한다. 다인 품목 접수가 아닌 묶음 완료로만 단계가 오른다.
- 기존 R3: 서버가 활성 명단·유일 단독 진행자를 확정한다. 복귀/대기/다른 점포 권한을 섞지 않는다.
- 기존 R4: 정전→기존 활성 주문 재개/종료→대기 진열 변경→다음 주문의 예외 순서를 유지한다. 여러 품목에도 같은 OrderId 계약을 적용한다.
- 기존 R5: 위치 신호5초와 정전 정보 지속 표시를 구분한다. 구간 재분할/일시 해제의 초기화 차이는 SP3가 우선한다.
- 기존 R6: 첫 시도와 둘째 학습 관찰·규칙검사·실제 플레이를 구분한다. V2는 기존2인 사용성 비율을 그대로 통과 판정에 재사용하지 않는다.
- 300초·주문45초·정전45초·불안도0~100·진열 변경1회·정전1회는 잠정 유지한다. 다인 적합성은 V2 이후 수정 가능하다.
- 외형 후보와 29/49/79 Robux 가설은 v0.2 P9의 후속 연구 값이며 이번 확장 파일은 실제 상품/가격을 확정하지 않는다.
- 점포 슬롯·팀 이동·정전 정보·복귀·연습·실패 완화는 판매하지 않는다. 무료 직접 제작 Part/텍스트 UI 범위를 유지한다.

## SD3. 독립 검토 S1·S2 반영 기록
- 근거는 Moderator가 전달한 NightShift-DesignReview의 실제 1차 검토 내용이다. 재현 조건은 규칙에서 도출한 시나리오이며 실제 실행 결과가 아니다.
- 두 건 모두 수용했다. 재검토에서 S2는 해결, S1은 동시 일반 반납/이탈 순서가 남아 부분 해결로 판정됐다. 아래 S1 잔여 경계 보완은 작성자의 문서 반영이며 독립 해결 판정/구현 검증을 대신하지 않는다.

- S1 불변조건: 유지된 미접수 품목마다 미수집/유효 운반자/트레이 중 하나만 성립한다. 소유권 회수 뒤 과거 요청은 상태를 바꾸지 못한다.
- S2 불변조건: 실제 입력에 필요한 담당자 수와 메모·도움말·HUD가 같은 인원/분할 상태를 따른다. 복구 대기와 단독 모드도 별도 표기한다.
- S2는 전달받은 재검토에서 해결 판정이었다. SP3.1 안내·인원별 표시와 SP9.1 S2-A/B 명세는 유지하며 실제 무음 이해도 검증은 여전히 미실행이다.

## SD4. 공식 참고와 이번 확인 경계
- 2026-10-31 [Instance streaming](https://create.roblox.com/docs/workspace/streaming)과 [Improve performance](https://create.roblox.com/docs/performance-optimization/improve)의 관련 설명을 읽었다.
- Workspace 로드/해제와 재바인딩, 잔여 연결/매 프레임 계산/물리 비용을 고려한 설계 근거다. Roblox가 자체 수치 예산을 보장한다는 인용은 아니다.
- 실제 한 일: 현행 지시/확장 원문 읽기, 전달된 S1 잔여 경계와 두 기대 사례를 두 확장 문서에 보완, 저장 후 재읽기와 UTF-8/상호 참조·원안 보존 확인(완료 응답에 결과 보고).
- 확인된 검토 이력: 1차 검토 수정 필요, 재검토 S2 해결/S1 부분 해결. 현재는 S1 잔여 문구 보완 후 독립 재검토 대기다.
- 아직 하지 않은 일: 코드/공유 규약 확정, Studio 조작, 로컬/다인/16인/모바일 실행, 실제 에셋 이용 허가와 판매 정책 확인.
- 다음 인계는 저장 확인 후 독립 재검토다. 수용/성능 목표가 충족됐다는 표현 없이 증거와 미실행을 함께 넘긴다.
