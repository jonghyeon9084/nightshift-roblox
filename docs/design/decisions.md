## D1. R1 적용의 구체적 변경
- 원안 ‘정전 처리 완료면 팀 성공’을 ‘공동 해결이면 협동 성공, 자동 복구면 지원 마감’으로 변경했다.
- 혼자 모드는 정전을 먼저 공동 해결했더라도 인원 조정 결과로 우선 분류한다. 실패 여부와 정전 방식은 별도 표시한다.
- 지원 마감에 영구 불이익·유료 보완책·콘텐츠 잠금을 두지 않는다. 정상 성공의 관찰 의미만 보존한다.
- 45초 정각은 자동 복구 우선이며 공동 해결은 45초 미만으로 통일했다.

## D2. R2 적용의 구체적 변경
- A: 성공 2건 뒤 진열, 3건 뒤 정전. B: 2건 뒤 정전→진열. C: 1건 뒤 진열, 4건 뒤 정전.
- 단계 3~5 또는 2~4에 상품 세 종류를 강제 배정하고 주문 ID에 상품을 연결해 미리 쌓아 둔 상품으로 변경을 건너뛰지 못하게 했다.
- 별도의 새 사건을 추가하지 않았다. 단순 경계 처리로 기존 진열·정전의 순서만 달라진다.
- 300초를 상한으로 바꾸고 목표 완료 즉시 마감한다. 기존 조기 마감 투표는 삭제해 동의 대기를 줄인다.
- 첫 주문 대기 10초와 후속 대기 8초는 즉시/최대 3초로 변경했다. 플레이 길이는 실측 후 조정한다.
- 이 변경은 ‘약 5분’ 원안에서 짧아질 수 있는 의도적 변경이다. 목표 없는 시간을 늘려 길이를 맞추지 않는다.

## D3. R3 적용의 구체적 변경
- 수동 선택·복구 예산 만료·온라인 무응답 모두 같은 혼자 확정 절차를 사용한다. 되돌리기는 다음 근무에서만 한다.
- 20초는 근무 전체 누적 예산으로 정했다. 반복 이탈로 정지 시간을 무한 연장하지 않는다.
- 온라인 요청은 근무당 한 번, 먼저 접수한 요청만 유효하다. 두 번째 동시 요청은 거부하며 상대는 별도 취소 버튼을 사용할 수 있다.
- 기한 정각의 준비/취소는 기한 처리 뒤에 오므로 모드를 되돌리지 못한다. 요청 중 이탈/종료는 요청을 취소한다.
- 혼자 전환 후 모든 대기자는 진행 요청 권한이 없다. 유일 진행자 이탈 시 남은 대기자에게 자동 승계하지 않는다.
- 온라인 무응답 전환이 상대에게 불쾌한지 역시 미검증이다. 명시적 안내와 취소 기회는 제공하지만 실제 반응 확인이 필요하다.

## D4. R4 적용의 구체적 변경
- 정상 일정은 활성 주문이 없는 경계에서만 사건을 실행한다. 불필요한 겹침 가능성을 우선 줄였다.
- 예외는 복구→같은 주문 ID/잔여 시간 재개→그 주문 종료→변경→신규/대체 주문으로 고정했다.
- 만료 벌점은 유지하고 대체 주문 생성만 변경 뒤로 미룬다. 중간에 주문을 조용히 취소하지 않는다.
- 발생이 드문 예외라는 이유로 검증에서 빼지 않고 개발 상태 주입 T4로 분리했다.

## D5. R5 적용의 구체적 변경
- 위치 신호만 5초, 정전 순서는 정전 종료까지 유지한다. 상태표가 UI·서버의 공동 기준이다.
- 오입력과 혼자 확정은 입력 진도를 0으로 만들고, 연결 취소·재연결·역할 교환·2인 복귀는 진도를 유지한다.
- 연결이 끊겨도 정답 순서를 숨기지 않는다. ‘입력 중지: 표시판 연결 필요’를 별도 표시한다.
- 정전/근무 종료에는 순서와 소유권을 폐기해 다음 근무의 오래된 정보로 입력하지 못하게 한다.

## D6. R6 적용의 구체적 변경
- 첫 시도 통과는 같은 2쌍 이상이 두 조건을 모두 달성하는 것으로 명시했다. 둘째 시도로 첫째 실패를 보충하지 않는다.
- 지원 복구·인원 조정·외부 도움은 협동 정전 사용성 통과가 아니다. 둘째 시도와 학습 관찰은 별도 집계한다.
- 실패 세션은 전원 원인 설명과 15초 안의 무도움 재도전 발견을 요구하며, 한 명이라도 중단 요청/비난 경험이 있으면 연출 수정 대상으로 둔다.
- 사건 중첩·중복 요청·정전/근무/이탈 경계는 사용자 성공률과 분리된 규칙 테스트로 지정했다.
- 모든 수치 기준은 검증 전 목표이며 작은 표본을 재미·매출의 일반적 증명으로 확대하지 않는다.
