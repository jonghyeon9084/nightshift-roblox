## 3. 단독 운영·소유권과 이전 계약의 변경 제안

아래는 공유 계약 담당에게 넘길 **제안**이다. API/스키마/상수 확정이나 구현 완료가 아니다.

- `OwnerUserId ↔ StoreId`는 서버의 세션별1:1 대응이다. 배정 세대/프로필 epoch를 검증하고 자리 번호를 저장 키로 쓰지 않는다. 로드 중·lease 상실·퇴장 중 경제 입력을 막고 자리를 이중 발급하지 않는다.
- 공용은 **이 서버 도매 공급 ledger**다. 주문 후 상품·매출·지갑·업그레이드는 개인 소유다. TeamSize/직원 참가·지원 권한·팀 보상·직원 수 연동 주문량과 UI는 승계하지 않는다.
- 기존 교대 예산/Wallet 분리는 최신 ‘판매로 돈 축적·개인 재고 저장’과 재조율해야 한다. **최소 제안은 개인 영업 지갑 하나**로 구매·환불·판매·업그레이드를 처리하는 것이다. 초기 자금은 새 프로필 생성 때 한 번만, 재접속/교대마다 지급하지 않는다. 예산 분리 유지 대안은 잔고·정산·보존 규칙을 독립 검토에서 확정한 경우만 가능하다.
- 창고/선반 소유품은 결산·자리 재배정 때 폐기하지 않는다. 미출발 주문·배송·운반·드롭을 저장 장벽에서 한 곳으로 귀속한다. 유효 구매 생성품만 복원하며 무한 선반·더미 상품 판매를 금지한다.
- **도난 경보와 영구자산 보호:** 기존 `SecureTheft`의 타인 프로필 편입은 제안 기준 비활성이다. 경보/운반 중 원소유권을 유지하고 회수 시간·퇴장·교대 종료 시 원소유 창고로 돌린다. 남의 상품 판매·저장 편입·도난/회수 점수 농사를 차단한다. 더 작은 대안은 시도 거절+서버 경보이며, 그 경우 실제 도난 운반 미구현을 명시한다. 기존 계약과 충돌하므로 검토/계약 확정 전 임의 구현하지 않는다.
- 무료 게임머니 업그레이드 최소1종은 자기 창고 용량 증가를 제안한다. 서버가 단계·소유자·가격표·잔액·중복 요청을 검사한다. 대회에는 기본 용량/도구 기준을 적용한다. 연습 영업은 무료 재시도가 가능하되 연습 돈/재고를 개인 저장·공유 ledger·대회로 편입하지 않는다. 연습은 정상 경제 완주 증거를 대신하지 않는다.

## 4. 기한 내 재방문 2개

시간·점수·구매량과 재미/유지율 효과는 **미검증 가설**이다. 아래는 독립 검토 전 제안이며 채택/구현 완료가 아니다.

### R-A. 예고된 변동 수요·소량 발주 목표

5분 회차와 준비 안내30초를 제안한다. 기본품2종의 `각2개 실제 판매` 목표를 PC에 미리 표시하고 시작 뒤 바꾸지 않는다. 가격/확률 배수 없이 발주·진열 선택을 바꾼다. 미달 벌금·재고 소멸·해금 잠금 없이 일반 영업을 계속한다. 회차 새 판매 거래로만 진도를 쌓는다.

공유재고 선점 방지가 필수다. 제안: 목표 기본품 일부를 도매 ledger 안에서 활성 소유자별 동일 소량 주문 몫으로 유보하고, 미사용 몫은 안내된 시각 후 공용으로 해제한다. 유보+공용+예약 합은 실제 공급량을 넘지 않는다. 신규 참가자에게 목표품 접근이 없으면 가용품 대체 또는 다음 회차/일반 영업을 제공한다. **더 작은 대안은 ‘가용 기본품 중 서로 다른2종’ 목표**로 바꾸는 것이다. 마지막1개 경쟁은 유보 밖 공용분에서 검사한다.

전원 같은 수요를 보고 다음 회차에도 동등하게 참여한다. 시간대 한정 희귀품·스트릭·오프라인 손해·접속 알림 강요는 없다. 최소안 목표 보상은 무료 실적 표시뿐이며, 일반 판매는 기존 가격을 유지한다. 목표 못 채워도 정상 성장 가능하다.

### R-B. 짧은 서버 영업대회

참가 선택자를 다음 준비 단계에 등록한다. 매출액/초기재산 대신 아래3부문을 평가한다. 제안 총점100=30/40/30이며 최소안은 부문 결과판만 남겨도 된다.

| 부문 | 인정 규칙 제안 | 농사·선발자 우위 방지 |
| --- | --- | --- |
| 다양한 판매30 | 새 기본품 서로 다른 최대3종 실제 구매, 종당10 | 고가·희귀품/부자손님 수량/매출 배수 무관. 같은 SKU 반복 추가점0 |

기존 자산이 많은 사람도 대회에는 **이번 회차 새 발주 기본품**만 인정한다. 기본 도구·진열 수·회차 인정 발주 상한을 동일하게 적용한다. 무료 상위 도구·창고 용량·이전 재산·유료 외형은 인정 속도/상한 보너스를 주지 않는다. NPC 배정 운이 점수를 지배하면 참가자별 동등 최소 일반 손님 기회를 분배하는 대안을 검토한다. **동등 기회를 보장 못하면 승패/경제 보상은 보류하고 개인 실적만 표시**한다.

최소 보상은 회차 기록/문구로 한정해 지갑·재고 지급 경합을 줄인다. 부문 동점은 공동 기록한다. 늦은 참가자는 불리한 잔여 시간에 강제 투입하지 않고 일반 영업/개인 연습/다음 회차를 선택한다. 1명이면 개인 목표이며 가짜 상대를 표시하지 않는다. 퇴장해도 영구 자산·해금 보존. 참가비·연속 접속/연승 보너스·유료 승리·영구자산 약탈 점수는 없다.

### R-C. 후속 후보: 전문화·단골 관계

R-A/R-B 두 회차 관찰 뒤만 착수한다. ‘아침 기본식/간식’ 선호 테마·일반 NPC 단골 문구부터 제안한다. 유료 친밀도·부자손님 확률 상승·오프라인 관계 하락·재방문 숙제는 없다. 추가 관계 저장·복잡한 가격전략은 마감 뒤다. 지금은 채택하지 않았다.

## 5. 권한·저장 API 제안

기존 `Action/State`, `Context`, `Result={Ok,Code,Value}`, 서버 직렬 큐·ProfileService 어댑터를 재사용하고 Remote를 중복 생성하지 않는 방향이다. 명칭/필드/오류코드는 `solo_store_contract`가 확정한다. [기술 근거](retention-benchmark.md)의 공식 설명과 아래 자체 제안을 구분한다.

| 경계 | 서버 내부 API 제안 | 반드시 보장할 조건 |
| --- | --- | --- |
| 소유권 | `assignOwner(userId,profileEpoch)`, `getOwnerContext(player)`, `releaseOwner(userId,generation)` | 클라이언트 Owner/가격/잔액/단계 불신. 오래된 배정 세대·epoch 거절 |
| 영업 | 기존 `action(context,action,payload)`로 주문/입출고/진열/업그레이드 | 타입·키·정수 범위·NaN/무한·빈도·거리/시야·소유권·revision·요청ID 검증. 방문 권한으로 남의 관리 불가 |
| NPC | `commitNpcSale(storeId,npcId,itemIds,expectedRevisions,transactionId)` | 서버가 선택한 실제 Shelf품 원자 차감/돈 증가. 판매·도난·회수·퇴장 같은 큐, 실패 전부 불변 |
| 충돌 | `dropCarried(context,collisionEventId,safePosition)` | 서버 접촉·속도·이벤트 중복 검사, 원소유 상품만 이동. 돈/영구총량 불변. 기존 규약이 즉시 회수면 그 동작을 정확히 보고 |
| 실적 | `recordVerifiedSale(event)`, `viewContest(userId)` | 클라이언트 점수 제출 금지. 정상 커밋 거래ID/회차/상품 계보/기본품 자격당1회 |
| 저장 | 기존 `load/get/mutate/save/status` + 상품 snapshot/복원 장벽 | 성공한 load·현재 lease/epoch, 세션 잠금·revision·중복 복원 검사. 저장 중 추가 변경 revision 보존 |

UserId 저장 키와 명시적 migration을 사용한다. 제안 필드는 schemaVersion/revision/sessionLease, wallet/XP/level/upgrades, warehouseItems/shelfItems(영속ID·SKU·수량·slot), discoveries/achievements, 거래/복원 커서다. StoreId·Instance·클라이언트 token·NPC 객체는 영속 소유권으로 저장하지 않는다. 기존 스키마에 개인 재고가 빠진 문제를 검토에서 처리한다.

**복원/보존:** 저장 장벽에서 경제 입력을 잠시 정지하고 주문·배송·운반·드롭을 취소/원소유 창고로 귀속한 뒤 같은 개인 snapshot을 만든다. 선반·창고·잔고·업그레이드가 일치하는 revision만 저장한다. 재접속 빈 매장 배정 뒤 epoch당 복원1회, 실패하면 부분 표현 회수·입력 잠금 유지. 비용 청구 후 인도 전 퇴장은 ‘취소 환불’ 또는 ‘인도 완료’ 중 한 정책만 수행한다.

타인 프로필로 상품을 이전하지 않는 최소안으로 개인 키 간 원자 거래 위험을 줄인다. 공용 도매 ledger는 서버 수명 범위이며 cross-server 시장은 범위 밖이다. 서버 공급 초기화가 개인 자산 복제 원인이 되면 실패다.

서버 전용 `UpdateAsync` 콜백은 yield·외부 부작용 없이 revision/lease를 검사한다. 로드 오류·새 스키마·손상을 신규값으로 덮지 않는다. 실패는 제한된 백오프 뒤 명시 오류/경제 입력 정지를 유지한다. 자동/퇴장/종료 저장은 멱등이어야 하며 종료 저장 성공을 보장한다고 쓰지 않는다. Memory 어댑터는 UI/로그에 임시로 표시한다. **모의 어댑터·동일 프로세스 Memory 재접속은 클라우드 영속 증거가 아니다.** 기존 승인된 테스트 경험이 없으면 게시 없이 클라우드 검증을 할 수 없다는 제한을 보고한다.
