## P1. 핵심 경험과 구현 범위
- 핵심 경험: 두 야간 직원이 편의점 주문을 전달하고 서로 다른 위치의 정보를 합쳐 정전을 해결한다.
- H1: 정보 전달과 공동 해결이 협동 만족을 만든다. 일반 주문은 혼자 가능하지만 협동 성공에는 실제 공동 정전 해결이 필요하다.
- H2: 바뀐 진열에서 다시 상품을 찾고 사건 순서에 맞춰 역할을 바꾸는 행동이 반복 플레이의 차이를 만든다.
- H3: 명확한 원인 안내와 무료 재도전이 실패 후 불쾌함을 줄인다. 세 가설 모두 미검증이다.
- 2인·매장 1개·계산대·진열대 3개·작은 창고·표시판·차단기만 구현 대상으로 둔다.
- 상품은 물·빵·우유 3종, 주문 성공 5건, 진열 변경 1회, 정전 1회가 필수다.
- 300초는 근무의 상한이다. 목표를 일찍 마치면 자동 마감하며 5분을 채우려고 기다리게 하지 않는다.
- NPC·추격·전투·개인 사망·영구 재화·저장·서버 간 매칭·4인·추가 맵은 제외한다.
- 무료 조작 도구와 기본 외형으로 모든 일정·결말·재시작을 이용한다. 지원 결과가 콘텐츠를 잠그지 않는다.
- 기본 루프 검증 후 로컬 꾸미기 미리보기를 붙일 수 있지만 실제 상품 ID·결제·판매 활성화는 별도 범위다.

## P2. 주문과 30초/5분 루프
- 대기실에서 두 사람의 준비와 간단한 조작 안내를 마치면 새 근무 ID로 시작한다.
- 첫 주문은 근무 시작 즉시 보이고 제한 시간 45초가 시작된다. 사전 안내 시간은 근무에 포함하지 않는다.
- 활성 주문은 최대 1건이며 번호·성공 단계(1~5)·이름·도형·남은 시간을 모두에게 표시한다.
- 각 단계는 상품 한 종류 1개를 요구한다. 만료 시 불안도 +15, 성공 단계는 유지한다.
- 만료 주문은 새 주문 ID로 같은 상품을 재요청한다. 성공한 주문만 단계와 사건 진행을 바꾼다.
- 주문 종료 후 보통 3초 안에 다음 주문을 낸다. 경계 사건이 있으면 P3 순서를 먼저 수행한다.
- 상품은 현재 주문 중 진열대에서 집는다. 재고는 무제한이고 각자 한 개만 들 수 있다.
- 들고 있는 상품은 주문 ID에 연결한다. 선취·비축은 없고 주문 종료 시 남은 복제 상품은 무료 회수한다.
- 잘못 집은 상품은 무료 반납 가능하다. 이름·도형과 현재 진열 위치를 보고 다시 고른다.
- 계산대에 유효 상품을 전달하면 완료한다. 고정 계산 담당·유료 도구·별도 승인 버튼은 없다.
- 양쪽이 동시에 전달하면 첫 유효 요청 한 건만 처리하며 나머지는 ‘이미 완료’로 알린다.
- 30초 사례: A가 현재 주문을 보고 위치 신호 → B가 바뀐 진열에서 찾고 전달 → 둘이 정전 역할을 나눈다.
- 전체 흐름은 주문 → 진행 단계에 따른 진열/정전 → 남은 주문 → 자동 마감이며 절대 시각 사건은 없다.
- 5건 성공과 필수 사건 처리 완료 시 남은 시간에 관계없이 결과로 전환한다. 조기 마감 투표는 제거한다.
- 의도된 필수 행동 없는 대기는 경계 안내 최대 3초뿐이다. 연결 복구 대기는 별도로 기록한다.
- 정전 중에는 두 사람에게 계속 조작 과제가 있으므로 무입력 45초는 ‘대기 설계’가 아닌 미수행으로 기록한다.
- 아무 행동을 하지 않더라도 주문 만료·정전 자동 복구·근무 상한이 작동해 무한 진행 상태를 만들지 않는다.

## P3. 밤 변형과 사건 순서 — R2·R4
- A/B/C는 같은 첫 밤의 규칙 변형이다. 스토리의 후속 2·3밤 콘텐츠와 구분한다.

| 일정 | 첫 사건 | 두 번째 사건 | 진열 변경 뒤 필수 성공 주문 |
| --- | --- | --- | --- |
| A | 성공 2건 직후 진열 변경 | 성공 3건 직후 정전 | 단계 3·4·5 |
| B | 성공 2건 직후 정전 | 그 정전 복구 직후 진열 변경 | 단계 3·4·5 |
| C | 성공 1건 직후 진열 변경 | 성공 4건 직후 정전 | 단계 2·3·4·5 |

- 주문 성공을 확정한 뒤 사건 대기를 등록한다. 만료는 사건을 당기거나 같은 사건을 반복시키지 않는다.
- A/B의 단계 3~5, C의 단계 2~4에는 물·빵·우유를 각각 한 번 배정해 변경 후 세 진열대를 모두 사용한다.
- 나머지 단계의 상품도 시작 때 정한다. 같은 세션 재시작에서는 직전과 다른 일정, 가능한 다른 초기 배치를 고른다.
- 초기 배치는 3종의 6개 순열이며 진열 변경은 세 상품을 한 칸씩 순환한다. 통로와 접근성은 유지한다.
- 변경 예고 3초 후 위치를 갱신하고 새 주문을 즉시 낸다. 별도 주문 대기 3초를 다시 더하지 않는다.
- 정전 복구 후 변경이 없으면 다음 주문을 3초 안에 낸다. B는 변경 예고 3초가 이 간격을 대신한다.
- 변경 전 주문 ID의 상품을 변경 후 주문에 쓸 수 없어 빠른 팀도 변경된 위치에서 새로 집어야 한다.
- 호출벨은 단계 3 주문 생성 시 빈 통로 표지와 약한 소리로 한 번 표현한다. 과제·벌점·고객 탐색은 없다.
- 정전과 진열 변경은 동시에 실행하지 않는다. 같은 경계에서는 정전 → 진열 변경 → 새 주문 순서다.
- **예외 우선순위:** 활성 주문이 있는 채 변경이 대기하고 정전이 발생하면 정전 복구 → 기존 주문의 같은 ID/잔여 시간 재개 → 그 주문 종료 → 대기한 진열 변경 → 다음 주문 순서다.
- 이때 기존 주문 만료는 +15와 대체 주문을 예약하지만, 대체 주문보다 대기한 변경을 먼저 실행한다.
- 정전 중에는 기존 주문 전달을 거부하고 상품을 보존한다. 복구 직후 위치는 아직 바꾸지 않는다.
- 정상 일정은 활성 주문이 없는 경계에서만 사건을 내지만, 위 예외도 개발 검증용 상태 주입으로 확인한다.
- 각 사건은 근무별 ‘대기/진행/완료’ 상태를 한 번씩만 거친다. 중복 트리거로 변경·복구·주문을 재생성하지 않는다.
- 사례: B에서는 두 주문 뒤 정전을 함께 고치고 바뀐 진열에서 세 종류를 찾는다. A는 진열에서 한 번 찾은 뒤 정전을 맞는다.
- 빠른/보통/만료 팀 모두 성공 마감하려면 변경 후 상품을 최소 3회 새로 집어야 한다. 시간 초과 실패는 강제로 연장하지 않는다.

## P4. 무음 조작과 정전 정보 — R5
- 키보드 상호작용 키와 터치 버튼에 집기/전달·반납·위치 신호·순서 공유·취소를 동일하게 제공한다.
- 위치 신호는 목적지·발신자·‘여기 물/표시판 맡음/차단기 부탁’ 문구를 5초 표시한다. 발신 간격은 1초다.
- **정전 순서 공유는 위치 신호와 별개다.** 공유된 도형 순서는 해당 정전 종료까지 고정 영역에 남는다.
- 정전 ID별로 원·삼각·사각의 순열 하나를 사용한다. 정전 도중 정답을 바꾸거나 반복 도형으로 속이지 않는다.
- 표시판 담당은 현장에서 연결을 켜고 직접 ‘순서 공유’를 누른다. 연결 유지에는 계속 누르기가 필요 없다.
- 이동·취소로 연결을 끊으면 차단기 입력만 중지한다. 공유한 순서와 맞춘 입력 진도는 보존한다.
- 차단기는 공유 완료 상태이며 다른 활성 참가자가 표시판에 연결되어 있을 때만 입력을 받는다.
- 한 사람이 두 지점을 동시에 소유하지 못한다. 역할 교환은 양쪽 소유권을 풀고 다른 사람이 다시 연결한다.
- 연결 재개 시 보존된 진도에서 이어간다. UI는 정답 순서·맞춘 개수·중지 이유를 동시에 표시한다.
- 음성·소리·색 구별 없이 도형과 문구만으로 완료 가능해야 한다. 공유 정보는 역할을 바꾼 사람에게도 보인다.

## P5. 정전 시간과 결과 분류 — R1
- 정전 중 주문 제한/신규 주문 대기만 멈추고 근무 시간은 흐른다. 이탈 복구 대기는 P6에 따라 모두 멈춘다.
- 정전 유효 경과 15초·30초·45초마다 불안도 +10을 각각 한 번 부과한다.
- 유효 경과 45초 미만에 실제 두 사람의 연결·공유·정답 입력을 끝내면 ‘공동 해결’로 확정한다.
- 45초에 도달하면 먼저 마지막 +10과 자동 복구를 적용하고 ‘지원 복구’로 확정한다. 정확히 45초 입력은 공동 해결로 보지 않는다.
- 혼자 마무리에서 직접 입력한 경우는 ‘단독 해결’이다. 어느 방식이든 영업은 재개하지만 결과는 구분한다.
- 불안도는 0~100이며 주문 만료/정전 지연만 증가시킨다. 70부터 증가 원인과 남은 목표를 보여준다.
- 종료 판정은 불안도 100 이상 실패 → 필수 목표 완성 마감 → 300초 상한 미완성 실패 순서다.
- 필수 목표는 성공 주문 5건·진열 변경 완료·정전 처리 완료다. 300초와 같은 시각 입력은 P7에 따라 거부한다.

| 근무 모드와 충족 상태 | 결과 표기 | 의미 |
| --- | --- | --- |
| 끝까지 2인 모드, 목표 충족, 공동 해결 | 협동 성공 | 실제 두 사람 공동 해결 확인 |
| 끝까지 2인 모드, 목표 충족, 지원 복구 | 지원 마감 | 정상 협동 성공으로 집계하지 않음 |
| 혼자 모드로 한 번이라도 확정, 목표 충족 | 인원 조정 · 마감 | 정전 방식은 별도 부기 |
| 목표 미충족 상한/불안도 최대 | 근무 종료 · 미완료 | 원인 표시, 혼자 모드였다면 인원 조정 부기 |

- 모든 결과에서 같은 무료 재도전·모든 일정 접근을 제공한다. 지원/인원 조정에 결제·영구 보상 차등은 없다.
- 결과는 주문 수·정전 방식·실패 원인·다음 행동 하나를 보여준다. 개인 비난·점프스케어·판매 문구는 없다.
- 지원 복구를 기다리는 전략의 빈도와 이유는 관찰할 대상이며 재미가 확보됐다고 단정하지 않는다.

## P6. 참가자 전환과 재시작 — R3
- 근무 상태는 ‘2인 진행 → 이탈 복구 대기 → 2인 재개 또는 혼자 진행 → 결과’로 구분한다.
- 참가자 상태는 활성/복귀 준비/대기자로 구분한다. 혼자 진행에는 활성 진행자 ID가 정확히 하나다.
- 최초 이탈 즉시 그 사람의 상품을 회수하고 모든 정전 소유권을 해제한다. 남은 사람 상품은 유지한다.
- 이탈 복구 대기에서는 근무·주문·정전·경계 안내 타이머와 모든 진행 입력을 정지한다.
- 복구 대기 예산은 근무 전체에 누적 최대 20초다. 복귀/재이탈로 새 20초를 지급하지 않는다.
- 남은 사람은 즉시 혼자 마무리 또는 대기실 복귀를 선택할 수 있다. 복귀 준비자는 이 선택의 진행자가 아니다.
- 원래 두 사람이 연결되고 모두 재개 준비를 완료하면 예산이 남아 있는 동안만 2인 진행으로 돌아간다.
- 기한과 같은 시각 준비는 늦은 요청이다. 예산 만료가 우선하고 그 이후 준비로 모드를 되돌리지 않는다.
- 예산 만료 시 해당 복구 대기를 시작할 때 남았던 참가자가 연결되어 있으면 그 사람을 진행자로 확정한다.
- 그 사람이 나가고 원래 이탈자가 돌아와 연결되어 있다면 돌아온 사람을 진행자로 확정한다. 아무도 없으면 근무를 폐기한다.
- 재개 뒤 다시 이탈하면 남은 예산만 사용하고, 예산이 0이면 연결된 생존 참가자로 즉시 혼자 진행을 확정한다.
- 연결된 상대가 응답하지 않을 때는 도움말에서 혼자 진행을 요청할 수 있다. 상대에게 10초 취소 기회를 표시한다.
- 온라인 전환 요청은 근무당 한 번만 열고 서버가 먼저 접수한 요청 하나만 채택한다. 동시 두 번째 요청은 ‘요청 진행 중’으로 거부한다.
- 요청자에게 ‘완료되면 당신만 진행, 동료는 다음 근무 대기’를 표시한다. 상대는 명시적 취소 버튼으로 유지할 수 있다.
- 10초 동안 근무 타이머는 유지한다. 기한 전에 취소되면 2인 상태를 유지하고 재요청은 허용하지 않는다.
- 요청 기한과 같은 시각 취소는 늦다. 요청자가 연결되어 있고 근무가 진행 중이면 요청자를 유일한 진행자로 확정한다.
- 요청 대기 중 이탈하면 온라인 요청을 취소하고 이탈 복구 규칙으로 이동한다. 근무 결과가 먼저 나오면 요청을 취소한다.
- **수동 선택·20초 자동·10초 무응답 전환은 같은 확정 절차를 사용한다:** 모드 고정, 진행자 1명 지정, 나머지 대기, 정전 소유권 해제, 입력 진도 0, 순서 직접 공개.
- 확정 시 주문 ID·잔여 시간·성공 수·불안도·정전 경과·부과 이력은 보존한다. 대기자 상품만 회수한다.
- 자동/수동 구분 없이 이후 복귀자는 대기자다. 대기자의 전달·집기·차단기·신호·마감 요청은 모두 거부한다.
- 대기자는 현재 결과를 보거나 대기실로 나갈 수 있다. 혼자 진행자가 이탈하면 대기자에게 넘기지 않고 근무를 종료한다.
- 혼자 모드는 해당 근무 동안 되돌리지 않는다. 단독 상태를 정상 협동 성공에 섞지 않는다.
- 결과 후 현재 연결된 최대 두 참가자는 대기 상태로 돌아가며 둘 다 준비해야 새 2인 근무를 시작한다.
- 혼자 남은 사람은 대기실에서 기다리거나 같은 규칙의 혼자 연습을 명시적으로 선택할 수 있다. 연습 결과는 인원 조정으로 구분한다.
- 재시작은 새 근무 ID로 주문·상품·불안도·사건·연결·전환 요청·복구 예산·신호를 초기화한다. 이전 결과는 한 번만 확정한다.

## P7. 서버 판정 순서와 예외 계약
- 서버가 근무/주문/정전 ID, 현재 참가자 권한, 소유 상품, 조작 거리, 사건 상태를 검사한다.
- 동일 시각의 우선순위는 연결 이탈 → 300초 근무 기한 → 복구/전환 기한 → 정전/주문 기한 → 일반 사용자 입력이다. 해당 시각까지 이미 경과한 기한은 이탈 정지로 취소하지 않는다.
- 같은 종류 입력은 서버 접수 순번으로 직렬 처리한다. 클라이언트 시각으로 과거 유효 요청을 주장할 수 없다.
- 기한 전 접수 입력은 해당 기한보다 먼저 처리한다. 기한과 정확히 같으면 만료/전환/자동 복구가 먼저다.
- 기한 처리로 불안도 100이나 결과가 확정되면 나머지 진행 요청을 거부한다. 결과가 나오면 예약 사건도 취소한다.
- 주문 완료는 검사와 완료 확정을 한 처리 단위로 묶어 성공 수를 한 번만 올린다. 만료한 주문의 지연 전달은 거부한다.
- 모드 전환도 한 번만 확정한다. 전환 이후 같은 시각의 전 대기자 요청은 바뀐 권한으로 검사한다.
- 이탈과 진행 입력이 같은 시각이면 이탈을 먼저 처리하므로 복구 대기 중 주문이 완료되지 않는다.
- 동시성 시나리오는 구현에서 검증해야 할 계약이다. 이 문서로 실제 안전성을 통과 처리하지 않는다.

## P8. 접근성·스토리 최소 통합
- 필수 정보는 이름·도형·문구로 제공하고 소리/색만으로 구별하지 않는다. 정전에도 길과 버튼은 읽을 수 있어야 한다.
- 섬광·화면 흔들림·큰 비명·피를 넣지 않는다. 확대 글씨와 모바일 UI가 주문·순서·버튼을 가리지 않아야 한다.
- 장식 여부에 관계없이 상품 이름·도형·윤곽과 단서 시인성이 같다. 가리는 장식은 채택하지 않는다.
- story.md의 배경을 채택한다: 전달되지 못한 주문을 기억하는 가게가 다른 밤의 진열을 꺼낸다.
- 첫 밤은 메모 Part 하나와 기존 시작/정전/복구/결과 UI의 짧은 문구만 사용한다. 추가 과제·타이머·컷신은 없다.
- 시작: “첫 야간이네요. 자리가 달라도 물건은 여기 있어요.”
- 메모: “주문 5건. 불이 꺼지면 매장 한 명, 차단기 한 명. 순서를 신호로 전해요.”
- 정전: “서로 다른 밤이 켜졌어요.” 아래에 실제 연결/공유 도움말을 함께 표시한다.
- 공동 해결: “지금 불빛이에요. 영업을 이어 가요.” 지원 복구: “비상등이 켜졌어요. 영업을 이어 가요.”
- 협동 성공: “오늘도 정상영업. 두 분도 퇴근하세요.” 지원 마감: “지원으로 오늘 기록을 마쳤어요.”
- 인원 조정 마감: “남은 기록을 마쳤어요. 오늘 근무는 여기까지.” 미완료: “오늘 기록이 섞였어요. 무료로 다시 시작할 수 있어요.”
- 성공 후크 한 줄은 선택 사항이며 미구현 후속 밤 시작 버튼/해금 약속을 붙이지 않는다. 2·3밤 서사는 후속 범위다.

## P9. 에셋·선택적 수익화
- 이번 단계에서 에셋을 반입하지 않는다. 기본 Part·직접 작성 UI로 첫 루프를 검증한다.

- 특정 에셋 허가나 최신 Roblox 정책 준수를 확인한 문서가 아니다. 채택 시 공식 Assets/Creator Store 자료와 확인일을 별도 기록한다.

- 매력은 친구에게 보이는 색/무늬와 세트 통일감으로 만든다. 동일한 단서 시인성과 무료 기본 외형을 유지한다.
- 로컬 미리보기는 ‘무료 미리보기 · 판매하지 않음’으로 표시하고 착용/해제만 제공한다. 구매 완료나 소유권 획득을 가장하지 않는다.
- 기본 재미 검사와 미리보기 검사는 별도 세션이다. 자동 상점·실제 상품 생성·판매 활성화는 이번 구현 기준에 포함하지 않는다.

- 유료 랜덤·부활·시간 절약·진행 우위·거짓 희소성·허위 할인·팀에 손해를 주는 구매 압박은 제외한다.
- 구매 없는 시안으로 가치 이해·외형 선호·낮음/기준/높음 가격별 선택 이유를 조사한다. 미성년 참여에는 보호자 동의와 무구매 조건을 마련한다.
- 작은 표본을 매출 보장으로 해석하지 않는다. 실제 상품 방식/지역 가격은 도입 전 공식 Passes/Regional pricing 문서를 확인하고 출처·확인일을 기록한다.

- 첫째/둘째 시간 차이는 학습 관찰값이다. 일정 차이도 있으므로 인과 효과나 일반적 재미 증거로 단정하지 않는다.
- 별도 실패 세션에서 3쌍 모두 결과의 실제 원인을 외부 도움 없이 설명하고 15초 안에 무료 재도전을 찾아야 한다. 누락한 쌍이 있으면 결과 UI를 수정한다.
- 비난으로 느낀 문구·강한 불쾌감·중단 요청은 한 건이라도 연출 수정 대상으로 기록한다. 재도전을 강요하지 않고 중단 이유를 선택적으로 듣는다.
- 실패 세션은 이탈 테스트와 분리해 진행하며 중단 세션은 통과로 표시하지 않는다. 미실행 항목은 빈 통과값 대신 ‘미실행’을 적는다.
- 기준 미달 시 신호·안내·주문 제한·배치를 수정한다. 콘텐츠/결제 추가로 결함을 덮지 않는다. 재미/수익 일반화에는 추가 실측이 필요하다.

## P11. 인계와 남은 확인
- R1~R6는 문서에 반영했으나 해결 확정은 독립 재검토와 구현 후 해당 테스트 결과를 기다린다.
- 메인은 이 문서의 상태/ID/시간 계약을 기준으로 서버·UI·맵 작업을 나누고 Studio 편집과 테스트를 단독 조율한다.
- 이번 변경 파일은 plan.md와 decisions.md뿐이다. draft.md, story.md, 검토 기록과 코드 파일은 변경하지 않는다.
- 남은 미검증: 실제 동시 요청 처리·네트워크 이탈·모바일 가독성·새 진열 탐색·협동 만족·실패 감정·가격 수용도·에셋별 권리와 최신 정책.
