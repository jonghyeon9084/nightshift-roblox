# 09:00 릴리즈 범위 독립 검토

작성: NightShift-DesignReview / NightShift-ReleaseScopeReview / `release_scope_review`.
검토 입력: PM 초안과 최신 요구, 최종 실플레이 검사표. 이 문서만 작성했으며 게임 코드·공유 계약·큐·Studio는 변경하지 않았다.

## 1. 결론과 시각

**수정 조건부 범위 채택을 권고한다. 게임 출시 준비 완료 판정은 보류한다.** 1인 1매장·8명, 개인 자산 보존, 실제 물류/NPC 구매, 교통/드롭, 도난/경보, 무료 성장·경쟁·재방문, 공간/광고/UI, 최종 로컬 파일을 모두 남긴다. 필수 기능을 빼서 마감을 맞춘 것으로 보고하면 안 된다. 이전 2인 직원·16인 공동매장·팀 자금은 폐기된 설계다.

- 실제 로컬 시각 확인: PowerShell `Get-Date -Format 'yyyy-MM-dd HH:mm:ss K'` → **2026-11-01 00:57:58 +09:00**. 마감 **2026-11-01 09:00 KST**까지 **8시간 2분 2초**이며 이 확인 시점에는 지연이 아니다. 최종 자체 검사 시각은 7절에 추가한다.
- 같은 조회에서 `docs/implementation/solo-store-contract.md`, `docs/implementation/release-studio-report.md`, `.setup/release-verification.json`은 **없음**을 확인했다. 구현 전체가 없다는 뜻은 아니지만, 최종 계약·실플레이 완료를 뒷받침하는 이 지정 산출물은 확보되지 않았다.
- 일정 가능성은 **고위험·미입증**이다. PM의 시간표는 목표이지 실제 소요시간 측정이 아니다. 8시간 안에 끝난다고 보장할 근거가 없으며, 필수 실패/미검증이 남으면 `releaseReady=false`와 미완료 사유를 보고한다.
- 이 문서의 수용/변경/보류는 독립 검토자의 권고다. Moderator의 결정·PM 반영·서버 계약 확정·게임 구현·테스트 통과와 구별한다.

## 5. 마감까지 실행 순서와 조건

P L146~152의 목표 시간은 유지하되 확정 ETA로 쓰지 않는다. 계약→단독 소유/저장→NPC→교통→독립 코드검토→Studio 수정/재검증은 긴 직렬 경로다. UI/World/독립 모듈만 계약 확정 뒤 파일 소유권을 나누어 병렬 진행할 수 있다. 이번 검토자는 별도 워커를 생성하지 않았다.

1. **즉시~02:00 목표:** Moderator가 DR01~12 수용·변경·보류를 결정하고 PM/계약 담당에게 전달. D1 개인지갑, D2 임시 도난, D3 공급 기회, D4 대회 기회, D5 저장 장벽을 고정. 수요/대회·영구 실적·최종 인계 작업의 소유자와 선행을 연결한다.
2. **05:00 목표:** 필수 최소 구현·모듈 검사 산출물 수합. 미달이면 전문화/단골·군중/차종·추가 공포·복잡한 장식·경제 대회 보상을 먼저 미룬다. NPC 판매·교통·도난·성장/경쟁·저장 자체는 빠진 상태로 완료 처리하지 않는다.
3. **06:00 목표:** 독립 코드 검토 뒤 Integrator 단독 Studio 소유권으로 전환. 저장/돈/권한/복제/낙하 실패는 해결·영향 재검증 전 출시 가능 판정 금지. 다른 워커는 Studio를 건드리지 않는다.
4. **08:00 목표:** M의 모든 ID에 실행 환경·실클라이언트 수·입력·전후값·로그/화면 경로·버전·시각 기록. 환경이 없으면 즉시 PENDING 사유를 남긴다. 기능 확대를 멈추고 결함 수정/재검증·인계 파일 정합성에 집중한다.
5. **08:45~09:00 목표:** 로컬 파일·해시·잔여 오류·미검증·실제 종료 시각을 PM gate로 전달. 09:00 이후라면 초과 시간을 계산해 지연을 보고한다. 기능/검증이 덜 끝나면 ‘미완료 검증본’이며 기한 통과를 합격 근거로 삼지 않는다.

## 6. 후속 연결과 책임

- **Moderator/Root:** 본 문서의 판단 권고 검토, 기존 작업 정의를 보존한 새 ID/추가 인계로 DR11 해결, 파일별 쓰기 책임과 실제 실행 로그 확인. 이 문서는 실제 위임/활성화 기록이 아니다.
- **PM:** P·B의 최종 기준을 M과 연결하고, 경보만 도난 대체/휘발 결과판/공정성 미입증 대회가 완료가 아님을 반영. D1~D5와 DR 판단·이유·담당·검사 ID를 결정 기록에 편입. E의 공식 설명/추론/접근실패 경계를 유지.
- **Server 계약 담당:** DR01~06을 `solo-store-contract`와 공유 규약으로 구체화. 상품 계보·소유/보유자·회차/점수·Profile 필드/오류 상태를 먼저 고정. 기존 Server/NPC/Traffic의 같은 파일 수정은 직렬로 조율.
- **독립 코드 Review:** 소유권·개인키·저장/migration·판매/도난/충돌/퇴장 경합·점수 농사·레거시 직원 경로를 검토. 설계 검토 표식으로 코드검토를 대신하지 않는다.
- **NightShift-Integrator:** M 전체와 T01~15, DR02/04/05/06/09/10 보완 검사를 실행·실패 수정·재검증. 실제 산출물은 `docs/implementation/release-studio-report.md`, `.setup/release-verification.json`, 최종 로컬 rbxl이다. Studio 조작은 이 역할만 수행한다.
- **플레이 이후 제한된 후속:** 첫 판매 막힘, 목표품/대회 기회 편향, 무료 정전 중단 중 실제 발견된 최대3건만 재현·화면/시간·완료조건을 붙여 독립 검토 후 다음 큐로 연결. 지금 발견했다고 꾸미지 않는다.

## 7. 실제 검사·문서 검토·미검증 구분

- **실제 실행:** PowerShell로 A/R/P/M/B/E/Q와 과거 retention 문서 읽기, 줄 번호 확보, 현재 시각 확인, 필수 입력 존재 확인, 지정 최종 계약/검증 파일 존재 조회, `git status --short` 확인. 필수 입력은 누락되지 않았다. 문서 조회 결과와 후속 산출물 부재는 1~2절에 명시했다.
- **실제 문서 검토:** 최신 요구와 PM 초안/최종 검사표를 대조해 DR01~12, D1~D5 판단 권고, M 17개 ID 대응·담당·검사를 작성했다. 이는 독립 설계 검토이며 게임 기능 통과가 아니다.
- **모의 검사:** 게임 시뮬레이션·가짜 저장·점수 이벤트·로드 실패 주입을 실행하지 않았다. 문서 속 T/DR 절차는 미실행 검증 명세다.
