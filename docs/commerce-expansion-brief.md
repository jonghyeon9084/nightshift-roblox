# NightShift: 8개 편의점 경쟁·물류·성장 확장
이 문서는 2026-10-31 사용자의 추가 요구를 통합한 현재 구현 기준이다. 기존 로컬 1인 완주 버전은 보존하고 확장한다. 공개 Roblox 게임 게시·상품 판매 설정은 아직 하지 않는다. GitHub 소스 공개 요청은 별개이며 인증/실행 로그를 제외한다.

## 사용자 요구
- 하나의 직선 도로 양쪽에 4개씩, 총 8매장. +자 배치를 교체한다. 앞문은 도로를 향하고 사무실·창고·하역 공간·걸어 다닐 인도가 있다. 우선 서버 총 16명 목표, 매장당 최대 4인. 실제 인원 부하는 별도 검증한다.
- 사무실 PC에서 재고 주문 → 배송 트럭 도착 → 짐칸에서 직접 상품 운반 → 선반 칸에 직접 진열 → 손님 주문을 판매한다.
- 같은 서버 8매장이 하나의 가상 도매몰 재고를 공유한다. 실제 외부 쇼핑 사이트가 아니다. SKU별 유한 수량, 재입고 주기, 남은 수량을 모두에게 동일하게 보여준다. 마지막 재고 동시 주문·중복 요청·잔액 부족·예약 취소·트럭 회수의 원자적 처리 규칙이 필요하다.
- 기본 8종: 물, 우유, 탄산음료, 주스, 빵, 과자, 컵라면, 건전지. 종류/수량/원가/판매가/선반 슬롯/소유 점포/운반 상태를 서버가 관리한다. 일괄 자동 진열이 아닌 실제 직접 배치가 기본이다.
- 희귀 상품은 일부 재입고 회차에 소량 등장한다. 예: 별빛 젤리, 0시 우유, 야광 건전지. 게임머니로 직접 주문하며 유료 랜덤 상자·유료 선점·유료 재고 알림은 만들지 않는다. 이름/가격/등장 주기는 밸런스 가설이다.
- 다른 점포의 트럭 짐칸 및 진열된 상품을 훔칠 수 있다. 도난 성공 시 피해 점포에 경광등·상품명·위치 알림. 가능하면 무료/직접 생성한 짧은 경보음. 같은 팀 물건 이동은 도난이 아니다.
- 개인 게임머니·XP·레벨·해금 도구·꾸미기·매장 배치 프리셋·최고 기록·발견한 희귀 상품 목록을 재접속 시 복원한다.
- 개인/점포 기록 경쟁. 서버 내 점포 영업 실적과 개인 최고 기록, 이후 주간 기록. 서버가 확인한 성과만 기록하고 팀 인원/도구 단계/지원·연습 여부를 구분한다.
- Roblox 기본 근접 음성 채팅 지원 준비. 계정의 음성 자격·지역·연령 확인·마이크 동의는 Roblox 정책과 사용자 선택을 따른다. 강제 마이크 켜기·별도 녹음·전사·외부 음성 API 없음. 비음성 핑/경보/텍스트 안내로도 플레이 가능.
- 레벨로 핵심 기능과 도구를 무료 해금. 예: 손수레(자기 점포 운반), 재고 스캐너, 진열 프리셋. 첫 주문/기본 운반/판매/경보는 레벨이나 결제로 막지 않는다.
- 유료 후보: 특별한 외형의 도구, 추가 배치 저장 슬롯, 간판/유니폼 묶음. 무료 대응 기능을 제공하고 도난 성공률·희귀 재고 선점·경보 해제·랭킹 점수를 판매하지 않는다. 실제 Robux ID/가격/판매는 초안이며 결제 호출은 기본 비활성이다.
- 개발자 광고 수익을 위한 Roblox 공식 이미지 광고판을 거리와 매장 내부에 자연스럽게 배치한다. 기본은 도로변 간판 2개 + 각 매장 내벽 포스터형 1개이며, 실제 8매장에서는 총 10개다. 내부는 공식 규격 안에서 작은 면을 사용하고 직접 제작한 Part와 AdGui로 구성한다. 진열·주문·배송·도난·경보를 가리거나 통행을 방해하지 않는다. 영상 자동재생·강제 시청·게임 진행 제한·광고 시청에 따른 경쟁 보너스는 넣지 않는다. 광고 비대상·광고 미배정 시 공식 기본 대체 이미지를 사용한다. 설치 코드와 실제 광고 송출·수익 발생을 구분한다. 상세 설치와 검증은 docs/implementation/advertising.md에 기록한다.

## 구현 원칙과 초기 균형
- 점포 소속과 방문 위치를 구분한다. 기존 타 점포 경계 강제 복귀 로직을 그대로 두면 침입/도난이 불가능하므로 명시적으로 조정한다. 방문은 가능하지만 주문·금고·진열 관리 권한은 소속 점포만 가진다.
- 상품 인스턴스별 단일 운반자·버전/토큰·소유 점포를 둔다. 수량이 음수가 되거나 두 사람이 동시에 집거나 매도/취소/회수로 복제되지 않아야 한다. 거리/상태/시야/권한/속도/서버 시각을 검증한다.
- 초보 첫 영업과 빈 점포에 대한 반복 약탈을 제한한다. 도난 운반은 기본 한 상자/한 상품 묶음, 피해 점포별 재도난 대기시간, 일정 시간 안의 회수 기회를 둔다. 영구 해금/개인지갑은 훔칠 수 없다. 과도한 약탈이 수익 최적 행동이 되지 않도록 측정한다.
- 개인 저장 지갑과 교대별 점포 운영자금을 명확히 구분해 표시한다. 초기 공용 운영자금을 재접속으로 개인 영구 돈으로 복제할 수 없다. 합법적 판매/운반/협동 보상은 서버 발급 거래 ID로 한 번만 지급한다.
- 공유 재고는 서버 단위로 먼저 구현한다. 모든 Roblox 서버를 묶는 세계 재고는 이번 범위가 아니다. 매장별 주문 상한으로 한 매장이 전부 사들이는 상황을 제한하고 모두 같은 실재 재고를 본다.
- 저장은 DataStoreService 서버 전용, UserId 키, 스키마 버전, UpdateAsync, 세션 소유권/만료, 제한된 재시도/주기 저장/이탈·종료 저장. 로드 실패 때 기본값으로 기존 데이터를 덮어쓰지 않는다.
- 미게시 Place에서 실제 클라우드 저장이나 음성 연결을 통과했다고 하지 않는다. 주입 가능한 저장 어댑터로 충돌/장애/재로드를 시험하고 Studio 임시 상태는 명확히 표시한다. 게시·계정/보안 설정 변경이 필요하면 준비된 코드/검증/남은 단계로 기록한다.

## 재방문 기획
Planner는 첫 5분, 한 교대, 여러 날의 반복 흐름과 실패/도난 후 회복 동선을 설계한다.
- 처음에는 주문/하역/진열/첫 판매를 짧게 경험하고, 이후 경쟁과 희귀 상품을 소개한다.
- 친구와 주문 담당·운반·진열/계산·순찰을 자연스럽게 나눈다. 역할을 과금하지 않는다.
- 매번 다른 야간 사건, 상품 수요, 희귀 납품, 협동 목표로 재방문 이유를 만든다. 연속 접속 실패 벌점이나 놓치면 영구 손해인 보상을 기본으로 두지 않는다.
- 개인 가게 외형과 프리셋, 도구 숙련·수집 도감·주간 도전은 플레이 보상을 중심으로 한다.
- 첫 판매 완료율/소요시간, 첫 도난 후 이탈, 재도전, 친구와 재방문, D1/D7 유지율은 출시 후 측정할 가설 지표다. 현재 수익/재미가 검증됐다고 하지 않는다.
- P0 실제 거래·배송·진열·도난·저장 기반과 핵심 성장, P1 주간 변주/꾸미기 확장, P2 측정 후 이벤트/가격 조정을 구분한다.
