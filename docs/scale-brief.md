# 다인원·큰 맵 변경 지시

2026-10-31 사용자: 맵을 크게 만들고 많은 플레이어가 들어오게 한다. 2인 단일 점포는 최종 목표가 아니다.

- 메인 설계 가정: 한 서버 수용 목표 16명, 점포별 2~4인 팀, 최대 4개 팀. 실제 16인 성능/수용은 검증 전이다.
- 한 서버의 연결된 거리·중앙 광장·편의점 4개로 넓은 야간 동네를 만든다. 빈 거리만 늘려 필수 이동 시간을 늘리지 않는다.
- 같은 팀의 주문/불안/정전/승패는 팀/점포 ID로 격리한다. 타 팀이 주문을 제출하거나 차단기를 조작하지 못한다.
- 4명이 있을 때 2명만 일하고 나머지가 구경하는 문제를 검토한다. 첫 구현은 2~4명이 같은 루프에 유효하게 기여해야 한다. 새 대형 시스템은 줄인다.
- 기존 v0.2의 정확한 주문 ID, 예외 판정, 무음 플레이, 실패 후 무료 재도전, 시간 상한의 원칙을 유지한다.
- 2인 테스트판은 작은 검증 단위로만 남긴다. 최종 공간은 다인원 확장 가능한 구조로 구현한다.
- 도중 합류, 팀 꽉 참, 인원 감소, 이탈 복구/혼자 연습, 다른 팀 이동, 결과 후 팀 재결성 규칙을 명시한다.
- 작은 외형 변화/간판으로 점포를 구별한다. 맵/원격/서버 상태 계약을 Store01~Store04 중심으로 잡는다.
- 무료 직접 제작 Part·텍스트 UI만 사용한다. 교통 AI·대형 추격·영구 저장·공개 게시·실제 판매는 현재 구현에 추가하지 않는다.
- 모바일을 고려해 고정된 장식은 Anchored, 불필요한 그림자/조명/물리 부하를 줄인다. 스트리밍 시 없는 인스턴스에 클라이언트가 무한 대기하지 않도록 설계한다.
- 서버 MaxPlayers 16은 목표 설정이며 맵 크기만으로 수용/성능을 입증하지 않는다. 로컬 1~2클라이언트 검증과 실제 16인 부하 검증을 분리한다.
- 기본 맵 구조: Workspace.NightShiftWorld / Hub / Stores / Store01~Store04. 각 점포 StoreId 속성, Counter·Shelf1~Shelf3·SignalPanel·Breaker·Entry·Spawn 마커. 세부 계약은 구현 메인이 확정.
- 진행은 예약 시각을 기다리지 않는다. 현재 단계 결과→독립 검토→수정→구현→검증을 상주 실행기가 이어 간다. 제한에 걸리면 정직하게 중지하고 상태를 보존한다.

공식 성능 자료(메인 확인):
- https://create.roblox.com/docs/workspace/streaming
- https://create.roblox.com/docs/performance-optimization/improve
- 스트리밍은 도움이 될 수 있으나 설정만으로 성능 통과라고 보지 않는다. 실제 장치 측정이 필요하다.
