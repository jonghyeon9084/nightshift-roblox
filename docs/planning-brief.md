# 기획 협업 지시서

2026-10-31 사용자 승인 범위: 기획 워커와 독립 검토 워커가 실제로 초안·검토·수정안을 만들고 지도에서 진행을 확인한다. 필요한 역할은 추가 생성한다. 일반 실행과 UI 조작은 메인이 처리하고 매번 승인을 묻지 않는다.

## 고정 방향
- 밤마다 바뀌는 편의점, 가벼운 공포, 친구와 협동. 초기 2인, 추후 4인 검토.
- 스토리, 배경, 밤 변형의 이유, 짧은 사건과 결말도 메인·워커가 자율 기획한다. 스토리 워커가 만드는 `docs/design/story.md`가 도착하면 구현 전 기획에 통합한다. 과한 컷신·분기·텍스트로 반복 플레이를 방해하지 않는다.
- 기존 `docs/game-brief.md`는 시작 가설이다. 재미·완주 가능성을 위해 수정할 수 있으나 변경 이유를 기록한다.
- 무료이며 사용 조건을 확인한 에셋 또는 직접 제작·생성만. 외부 유료 API·유료 에셋 구매 금지. 첫 프로토타입은 기본 Part와 직접 만든 UI를 우선한다. 실제 에셋 반입은 이번 기획 범위 밖이다.
- 상업적 수익화 목적. 기본 협동 경험은 무과금으로 완결하고 외형·선택적 꾸미기 우선. 결제 우위, 고의적 불편, 실패 직후 결제 유도, 유료 랜덤 보상 제외. 수익/이탈 영향은 실측 전 가설로 표시.
- 사용자 후속 승인: 게임 아이템과 적절한 과금 요소의 자율 선정·로컬 구현도 진행한다. 기본 게임플레이 도구는 무료, 유료 후보는 선택형 외형·개인 장식을 우선한다. 실제 상품 ID가 없는 로컬 프로토타입에서는 미리보기로 표시하며 결제 성공·구매 완료를 가장하지 않는다. 공개 게시와 판매 활성화는 별도 단계다.
- 추가 사용자 요구: 구매하고 싶도록 상품 매력과 연출도 자율 설계한다. 착용·장식 미리보기, 친구에게 보이는 개성, 세트 구성과 명확한 가격·가치를 중심으로 한다. 이전의 과도한 과금 방지 조건은 유지한다. 거짓 희소성, 허위 할인, 결제하지 않으면 팀에 손해를 주는 구조는 넣지 않는다. 첫 버전은 무료 체험 미리보기이며 실제 상품 ID와 판매 설정 전까지 구매 가능한 것처럼 표시하지 않는다.
- 후속 사용자 지시: 기획 검토 이후 구현·Studio 테스트·수정까지 계속 개발한다. 현재 기획 그룹은 설계를 완성한 뒤 다음 구현 작업을 지정한다. 공개 상품 생성·게시·실구매는 실행하지 않는다.

## 산출물과 파일 소유권
- Planner: `docs/design/draft.md`, `docs/design/plan.md`, `docs/design/decisions.md`만 작성.
- DesignReview: 읽기 전용. 답변으로 독립 비판 보고. 루트 메인이 실제 원문을 `docs/design/review-log.md`에 보존.
- Moderator: 순서 조율, 실제 답변 전달, 완료 조건 확인. 스스로 두 워커의 작업을 대신하지 않음.

## 필요한 내용
핵심 재미 가설, 30초/5분 루프, 역할 전환과 혼자 해결 방지, 음성 없이도 되는 조작, 실제로 밤마다 무엇이 바뀌는지, 이길 수 있는 변형 조합, 사건 스케줄, 성공/실패·이탈·재시작, 낮은 공포 강도와 접근성, 작은 MVP/후속 범위, 무료 에셋 관리, 선택적인 수익화 후보 2~3개와 가격 검증 방식, 결제 노출 위치·빈도, 플레이테스트 관찰 항목과 판정 기준.

동시 주문 중복 완료·이탈 상태에서 정전 해제 교착·실패 후 불쾌함·상품 외형으로 정보 식별이 어려워지는 문제를 점검한다. 자동 상점, 저장, 수익화는 기본 재미 검증 이후 별도 단계로 분리한다.

## 반복 검토 방식
초안 → 독립 검토(이슈 ID·심각도·근거·대안·검증 방법) → 수정안과 이슈별 수용/변경/보류 이유 → 독립 재검토. 우선 한 회전, 치명적 미해결 문제만 추가 한 회전. 같은 내용의 무한 반복이나 의미 없는 점수 매기기를 하지 않는다. 재미를 검증됐다고 주장하지 않는다.

## 추가 워커
기존 워커가 해결할 수 없는 독립 전문 문제가 있을 때 목적·담당 범위·완료 조건을 정하고 `tools/New-NightShiftWorker.ps1 -Role <영문역할> -Responsibility <설명>`으로 생성한다. 등록 수 고정 제한은 없고 실제 동시 실행은 기본 1~2개, 최대 3개다. 자동화는 같은 작업을 중복 시작하지 않으며, 구독 한도 또는 인증 문제가 생기면 상태를 기록하고 멈춘다.
