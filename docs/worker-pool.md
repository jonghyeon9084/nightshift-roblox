# 작업별 워커 활성화와 모델 배정

상주 실행기는 게임 단계와 독립 작업 큐를 함께 관찰한다. `tools/worker-pool.json`에 목적, 담당 파일, 선행 작업, 완료 표식과 산출물이 있는 작업을 추가하면, 빈 자리에 배정하고 완료 후 워커를 비활성으로 남긴다. 역할 이름이 이미 있으면 재사용하고 없으면 공식 Codex가 연결된 Maestro에 등록한다. 등록 자체는 모델 호출이 아니다.

## 실행과 보존

- 기존 상주 실행기 프로세스 하나가 두 큐를 조정한다. 별도 분 단위 AI 예약 실행은 없다. `fs.watch` 알림과 2.5초 안전 조회가 사용되며 조회 자체는 AI 호출이 아니다.
- 다른 활성 Maestro 그룹의 참가자를 포함해 최대 4명을 확인한다. Moderator는 별도 세션으로 이 참가자 정원에 포함되지 않는다. 수동으로 별도 실행한 모든 프로세스를 강제 제어하는 OS 제한은 아니다.
- 새 배정 전에 최소 512 MiB 가용 메모리, 선행 작업, 쓰기/읽기 범위 충돌과 동일 참가자의 실행 여부를 확인한다. 읽기끼리는 병렬 허용한다. 이미 진행 중인 작업은 메모리가 낮아졌다는 이유로 강제 종료하지 않는다.
- 기존 작업 정의는 변경하거나 삭제하지 않는다. 새로운 작업 ID로 추가하며, 같은 워커 이름을 지정해 완료한 역할을 재사용할 수 있다. 부모 관계의 순환과 작업 의존성의 순환을 거부한다.
- 체크포인트, 원래 명령의 해시, 실제 그룹/응답, 완료 표식과 산출물을 대조한다. 완료한 작업은 재시작 후 다시 실행하지 않는다. 발행 여부가 불명확하면 자동 재전송하지 않는다.
- 오류·사용 한도·인증 문제는 검토 대상으로 남는다. 구독 한도를 다른 계정/제공자/API 키로 우회하지 않는다. 빈 큐는 대기하며 단순히 활동을 보이려고 무한 작업을 생성하지 않는다.

`.setup/worker-pool/`에는 각 작업의 체크포인트와 `events.jsonl`, `state.json`, 변경 방지용 `definitions.json`이 저장된다. Git에서는 제외한다. 활성/대기/완료 이벤트는 지도 이력에도 수집한다. 완료는 해당 산출물 확인이며 게임 출시나 Studio 통과를 의미하지 않는다.

## 지도

`parentName`은 명시적으로 배정한 **작업 소속**이다. 임시 PerfAudit와 PoolReview는 Dashboard 소속이다. 점선 소속 관계와 실제 그룹 통신선을 구분한다. 중앙 Moderator가 하위 워커에게 직접 보낸 명령은 실제 중앙↔하위 워커 경로로 표시한다. 부모가 명령했다고 꾸미지 않는다.

완료한 임시 워커는 삭제하지 않고 비활성으로 남겨 다음 배정에서 재사용한다. 완료 응답 후 Moderator가 검토 중인 상태와 참가자가 아직 응답 중인 상태도 별개다. 실제 모델/추론 수준은 `turn_context` 관측, 다음 작업 설정은 구성값으로 표시한다. Codex 내장 하위 에이전트와 Maestro 참가자는 별개이며 이 구현의 자동 큐는 Maestro 참가자를 사용한다.

## 세분화한 모델 정책

| 작업 | 설정 모델 | 추론 수준 |
| --- | --- | --- |
| 범위가 작은 확인·요약 | GPT-6 Luna | low |
| 작은 수정·정해진 검사 실행 | GPT-6.1 Terra | low |
| 확정 계약의 일반 구현 | GPT-6.1 Terra | medium |
| UI·문구·화면 구성 | GPT-6.1 Sol | medium |
| 여러 코드 경로를 추적하는 수정 | GPT-6.1 Terra | high |
| 기획·공유 계약 조정 | GPT-6.1 Sol | high |
| 저장·경제·권한·동시성·독립 검토·통합 | GPT-6 Astra | high |
| 재현 후에도 미해결인 복합 오류 | GPT-6 Astra | xhigh |

이는 이 프로젝트의 효율 최적화 정책이며 측정된 최적 조합이나 속도 보장이 아니다. 현재 PC의 모델 목록에서 모델과 지원 추론 수준을 확인한 뒤 배정한다. 실행 중인 참가자 변경은 거부하고 다음 요청 전에만 적용한다. 기존 게임 단계의 `simple/standard/complex`는 호환을 유지한다. `max/ultra`를 일괄 적용하거나 실패 때마다 끝없이 승급하지 않는다.

설정 근거: [공식 Codex 구성](https://learn.chatgpt.com/docs/config-file/config-basic), [공식 하위 에이전트 구성](https://learn.chatgpt.com/docs/agent-configuration/subagents). 실제 구현은 별도 API 호출 없이 기존 ChatGPT 로그인 공식 Codex를 사용한다.
