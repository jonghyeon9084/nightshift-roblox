# 출시 작업 연결 — 루트 통합 결정

2026-11-01 KST. 이 기록은 작업 배정·수용 결정이며 구현 또는 플레이 검사 합격 기록이 아니다.

## 기획과 실제 큐 연결

PM의 R-A 변동 수요/발주 목표와 R-B 짧은 다부문 영업대회는 독립 범위 검토 결과를 반영해 `solo_store_contract`에서 API·저장 여부·점수 인정 사건·수량/기회 한도·UI 스냅샷을 확정한다. `solo_store_server`의 기존 “PM에서 채택한 경쟁/변동 발주” 범위에 두 기능의 실제 구현과 검사를 명시한다. `solo_store_ui`가 연결하고 `npc_shopping`이 실제 거래 사건을 전달한다. 전용 작업 ID가 없다는 이유로 구현을 누락하지 않는다.

- 서버 담당은 DemandGoalService/ContestService처럼 작은 모듈로 나눌 수 있다. 지정 `src/server/` 소유권 안에서 Main/Protocol 연결까지 완료한다.
- 목표·대회는 실제 거래/개인 실적과 연결한다. 표시 전용 숫자, 운반 왕복 점수, 부자 손님 금액으로 압도하는 순위, 유료 승리는 제외한다. 구체 수치는 독립 검토·공유 계약 기준을 따른다.
- NPC 담당은 서버가 정한 단일 판매 API를 호출한다. 판매 수량·결제·진열 감소·목표/대회 사건이 서로 불일치하지 않는지 검사한다.
- Review/Integrator는 두 기능을 실제 핵심 루프의 일부로 확인한다. 문서만 있고 연결되지 않으면 GROW 미완료다.

PM 계획 자체는 3개 문서와 실제 Moderator 응답을 루트가 확인해 기획 인계로 수용했다. 독립 기획 검토와 게임 완성은 별도이며 아직 합격 처리하지 않았다.

## 광고 검토 수용

`rooftop-ads-review.md`의 R1~R4를 모두 수용한다. R2 시야 차폐·R3 월드 소유권·R4 표시 상태는 `release_world_polish`가 수정한다. R1 로더 연결은 최종 `release_studio_integration`이 소유하며 광고 모듈 설치와 외부 6면을 실제 검사한다. 리뷰 지적이 있다는 사실만으로 기존 4면 모듈이 Studio에 설치되었다고 표시하지 않는다.

## 독립 기획 검토 결정

루트는 `release-scope-review.md`의 DR01~12를 검토했다. DR01/D1 개인 지갑·migration, DR02/D2 임시 도난·실제 경보/회수, DR03/D3 기존 ledger의 목표용 소량 유보, DR04/D4 동등 인정 기회의 부문 대회, DR05 실적 영속 저장, DR06/D5 저장 장벽, DR07 첫 판매 안내·무료 회복, DR08 실제 NPC/충돌 행동, DR09 전체 시설/UI/광고면 검사, DR10 최종 Place 정합성, DR12 R-A/R-B 채택·확장 보류를 수용한다. 구현 소유자와 검사는 독립 검토표와 위 기존 큐 연결을 따른다. 실제 적용·검사는 아직 별도다.

DR11의 누락 방지 취지는 수용하되 추가 서버 작업 대신 기존 Server/UI/NPC/Review/Integrator의 **아직 발행하지 않은 프롬프트**에 R-A/R-B와 검사표·결정 문서를 명시했다. 기존 정의/해시는 바꾸지 않았으며 중복 코드 작성과 추가 기획 호출을 줄인다. 원소유권·기회 평등·저장 정책은 계약 담당이 공유 DTO로 고정한다.
